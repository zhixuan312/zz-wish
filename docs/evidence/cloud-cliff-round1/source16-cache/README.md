# Source16 cached cloud control

This is a frozen time-zero, LOW8 feasibility study. It preserves the actual Source16 density, source lighting and geometry as inputs, and measures the explicit loss from R8 spatial interpolation and an approximate directional-transmittance grid. It does not claim analytic field parity for the cache, motion acceptance, I11 post fade, final optical quality, full-size performance or public adoption. Original analytic GPU failures and rejected shader/readback attempts remain referenced in `handoff.json`.

The staged complete package is `art/build/cloud-cliff-round1/runtime-v16-cache-dda-delivery`. Its 21 requested files total **9,514,554 bytes including manifest**, or 9,914,554 with a 400,000-byte poster reserve. Main and HERO are lossless Zstd wrappers of the independently verified genuine F32 models. Cache KTX2 files use lossless Zstd over R8/RGBA8 typed texels; official KTX validation and the installed Three160 CPU decoder reproduce every raw byte. Logical cache GPU texels and retained decoded CPU texture data are **30,066,004 bytes each**; driver padding and actual GPU allocation are unqueried.

Global 2 m density plus a bounded 1 m near refinement reduces the worst alpha error on 20 actual view rays from 0.03558 to 0.00616. The lighting comparison weights transmittance by the same primary opacity, HG phase, source world/SUN radiance, cloud albedo and distance air. T8's worst sampled linear RGB error is 0.00315, with worst relative ray luminance error 6.96%; the much larger pointwise T error is reported separately. Half-float optical depth costs more and is slightly worse on these sampled RGB values. None of these empirical tests bounds all pixels or native multiple scattering.

The cached DDA shader has no analytic noise, child slab searches, secondary ray marches or dynamic private arrays. Its occupancy texture marks complete trilinear support footprints from both actual density caches. The 20-ray CPU study has no visible cap truncation, max 226 actual field samples and 245 iterations; steps are unchanged through 250 m and rise toward 4 m only farther away. The source cache and source17 proposals remain separate.

The final tiny control ran actual 16×16, 64×40 and 128×80 child FBOs with exact viewport assertions, 100 ms actual-draw stop, context/error/source guards and PNG acquisition synchronously in the existing after-render hook. It completed with zero errors and unchanged source fingerprints. Constant-fragment controls still report roughly 12–18 ms, while source draws are 6–17 ms; the timing does not scale with pixels. These values therefore support neither linear area extrapolation nor a full-frame/FPS claim. The original outside-RAF black read was invalid with `preserveDrawingBuffer=false`; no renderer setting was changed to repair acquisition.

`source17-post-medium-proposal/proposal.json` under `art/build/cloud-cliff-round1` proposes three camera-clear wisps with metres-long, varying post attenuation. It is not an authored source. Source16's proof of exactly zero medium between both cameras and every post remains valid and rejected for I11; actual scan cut silhouettes remain an I6 source defect. No Source17, full64 batch, full-size cache view or public installation has been performed.
