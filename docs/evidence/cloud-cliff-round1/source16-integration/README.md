Source16 integration study

The source, density field, materials, geometry, 45 W basis, world/SUN and views remain unchanged. This is a bounded numerical study of 20 actual desktop/phone view rays, not a CPU image render. It uses the actual delivered far256×192 and cliff256×512 heightfields and the recorded cover cameras. The latest measured pass took 0.53 seconds and about 900,000 density evaluations.

The 0.25 m versus 0.125 m reference alpha difference is at most 1.12e-5. The existing 48 global quadratic segments differ by up to 0.03908 in alpha and 20.83 m in constant-source scattering centroid. These are density/constant-unit-radiance quantities, not a native RGB or multiple-scattering equivalence claim.

The staged primary candidate intersects the actual child AABBs, merges their ray intervals, and skips empty space. Inside child supports it uses `min(3,.5+.003*viewDistance)` metres; substrate-only travel uses 8 m. The existing terrain heightfields clip a crossing segment with eight bounded bisections. The cap is 256 primary density samples. Across the measured rays, at most 244 visible samples are used, with zero visible cap truncations. Maximum alpha error is 0.001437 and centroid error 1.83 m. Naive fixed 0.5–0.75 m variants exhausted the cap and remain preserved as rejected study profiles.

Secondary light aliasing is separate. The existing 12 doubling segments show a maximum single-direction transmission error of0.722, including the actual SUN direction. The largest weighted six-axis world error is0.0362. Merely increasing sparse-light caps 32–96 still misses some distant sparse supports. An exact polynomial/Gauss substrate integral was tested numerically, with no FBM evaluations, but no secondary solver change is adopted. The first runtime candidate intentionally retains the current six-axis HG and 12-segment light functions byte-exactly.

The isolated descriptor and helper are in `art/build/cloud-cliff-round1/runtime-v16-primary-v1-stage`. Source16 field helper387b remains exact. HDR/depth compositing, terrain textures, distance air, local probes, point filtering, HERO construction and views are protected. Main/source11/public assets are unchanged. Actual shader compilation, cloud continuity, all-view cap coverage and performance require a bounded GPU review before adoption; no64 or source17 work is authorized.

`ray-study-summary.json` records the actual paths, complete hashes, candidate bounds, rejected light results and scope limits. Complete per-ray data remains in the ignored local study directory. The separate source-DAG/FMA arithmetic correction is linked from `../source16-low8/handoff.json`; old Double/uncontracted failures are retained.

The first primary-only GPU candidate is invalid. Its desktop framebuffer was entirely black; Chrome then reported context loss and blocked the phone context. The runner was stopped with exit 130 and all owned browsers closed. No visual or performance result is accepted. The failed artifact and incomplete original preflight/end-fingerprint scope are recorded honestly in its receipt. Subsequent capture guards record context-loss events and `isContextLost`, reject all-black RGB, persist preflight hashes before browser launch, and close the browser before recording failure. Actual failed/known-safe PNG fixtures exercise the black-frame guard without another GPU job.

The failed candidate increased the explicit worst-case density work from 4,080 calls to 21,760 per fragment. Its emitted shader grew from 20,353 to 23,921 bytes. These are code bounds, not driver IR, timing, or proof that a watchdog caused the failure. No relevant macOS GPU crash report was found.

The CPU-staged V2 separates fine extinction from source-light quadrature. It queries the next actual child support only at interval exits, with no private 48-entry array or insertion sort. Fine-step distance-air is integrated directly. The same six-axis/SUN solver runs at attenuated-scattering centroids for optical-mass cells; at most 25 light lookups are possible. The explicit density-call bound becomes 2,356, below the safe baseline. This changes quadrature, not source illumination, material values or the density field, and performs no output blur.

Across the same 20 rays, array-free scheduling uses at most 245 visible primary samples without cap truncation. The 24-cell profile uses at most 20 actual light lookups and differs by at most 0.000597 linear RGB from 0.25 m primary quadrature using the same 12-segment secondary solver. That reference is deliberately **not** a converged-secondary or native-lighting proof. Wider 12-group-only scheduling failed the cap and is rejected. V2 remains unrendered pending explicit review/lease; `budgeted-v2.json` records every input, stage hash, work bound and unresolved limit. No public or authored source change was made.
